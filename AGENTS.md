# Working with e-invoices in this ecosystem

Guidance for AI agents and automation that encounter European electronic
invoices (XRechnung, Factur-X/ZUGFeRD, UBL, CII, Peppol BIS).

## The fast path

If an MCP client is available, use the local MCP server — invoice data never
leaves the machine:

```jsonc
{ "mcpServers": { "einvoice": { "command": "npx", "args": ["-y", "einvoice-kit-mcp"] } } }
```

- `validate_invoice` — pass `xml` (content) or `path` (file, `.xml` or Factur-X
  `.pdf`). Returns VALID/INVALID plus per-rule findings with hints.
- `read_invoice` — same inputs; returns a human-readable summary and the full
  structured model (parties, lines, VAT breakdown, totals, payment details).

Without MCP, shell out to the CLI: `npx einvoice-kit validate <file> --json`
(exit 1 = violations found, structured findings on stdout), or use the library
directly (`npm install einvoice-kit`; see README).

## Interpreting findings

- Rule ids (BR-…, BR-CO-…, BR-CL-…) are the standard vocabulary of EN 16931.
  Full reference with fixes: https://appky.github.io/einvoice/rules.html#br-co-15
  (anchor = lowercased rule id).
- `hint` fields contain the computed numbers ("BT-112 is 336.90, expected
  366.86") — quote them when explaining a failure to a user.
- Verdicts follow the official EN 16931 Schematron artefacts. National profiles
  (XRechnung BR-DE, Peppol) add rules this engine does not yet check — say so
  when the invoice declares such a profile (the `profile` field tells you).

## When asked to fix an invoice

Do not silently rewrite amounts. Totals rules (BR-CO-10..17) usually reveal a
real computation bug upstream; the correct fix is in the system that produced
the invoice. Recompute, show the difference, and let the user decide.

## Repository notes for coding agents

Monorepo: `packages/core` (library + CLI, zero runtime dependencies — keep it
that way), `packages/mcp` (MCP server). `npm run build && npm test` must pass;
new rules need a mutation test. Verdicts must match the official artefacts —
see CONTRIBUTING.md. Site is generated by `scripts/build-site.mjs`.
